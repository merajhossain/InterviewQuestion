1. What is the Vercel AI SDK and how do you use it?

🔥 Trending 2026
Simple Explanation
An open-source SDK that makes it easy to build AI-powered streaming UIs in React and Next.js applications using providers like OpenAI, Anthropic, and Google.
Detailed Answer

The Vercel AI SDK provides three core layers:

  • AI SDK Core: Unified API for calling LLMs — generateText, streamText, generateObject.
  • AI SDK UI: React hooks — useChat, useCompletion — for streaming responses into the UI.
  • AI SDK RSC: Server-side streaming with React Server Components using streamUI.

It abstracts provider differences so you can switch between OpenAI, Anthropic, and Google Gemini with a single line change.

// app/api/chat/route.ts (Next.js Route Handler)
import { openai } from '@ai-sdk/openai';
import { streamText } from 'ai';

export async function POST(req: Request) {
  const { messages } = await req.json();
  const result = await streamText({
    model: openai('gpt-4o'),
    messages,
  });
  return result.toDataStreamResponse();
}

// components/Chat.tsx (Client Component)
'use client';
import { useChat } from 'ai/react';

export default function Chat() {
  const { messages, input, handleInputChange, handleSubmit } = useChat();
  return (
    <div>
      {messages.map(m => (
        <div key={m.id}>{m.role}: {m.content}</div>
      ))}
      <form onSubmit={handleSubmit}>
        <input value={input} onChange={handleInputChange} />
      </form>
    </div>
  );
}

2. How do you implement a streaming AI response in React?

🔥 Trending 2026
Simple Explanation
Streaming means the AI response arrives token-by-token, shown incrementally in the UI — exactly like ChatGPT typing effect. This is done via the Fetch API's ReadableStream.
Detailed Answer

The server sends a text/event-stream or chunked response. The client reads it via a ReadableStream decoder. Key concepts:

  • Server-Sent Events (SSE): The traditional way to stream server data to client.
  • ReadableStream: A Web API for reading streamed data chunk-by-chunk.
  • React Suspense + RSC: Allows streaming HTML from server to client in Next.js App Router.
// Manual streaming with Fetch API
async function streamResponse(prompt: string) {
  const response = await fetch('/api/generate', {
    method: 'POST',
    body: JSON.stringify({ prompt }),
  });

  const reader = response.body?.getReader();
  const decoder = new TextDecoder();

  while (true) {
    const { done, value } = await reader!.read();
    if (done) break;
    const chunk = decoder.decode(value, { stream: true });
    // Update UI incrementally
    setOutput(prev => prev + chunk);
  }
}

3. What is RAG (Retrieval-Augmented Generation) and why is it important?

🔥 Trending 2026
Simple Explanation
RAG is a technique where you first retrieve relevant documents from a database (vector search), then inject them into the LLM prompt so the AI answers based on your private data.
Detailed Answer

RAG solves two major LLM problems: hallucinations (making up facts) and knowledge cutoff (not knowing recent data).

The typical RAG pipeline:

  1. Embed: Convert user query into a vector using an embedding model.
  2. Search: Find similar vectors in a vector database (Pinecone, pgvector, Weaviate).
  3. Augment: Inject retrieved documents as context into the LLM prompt.
  4. Generate: LLM generates grounded answer based on the retrieved context.
// RAG pipeline with Vercel AI SDK
import { openai } from '@ai-sdk/openai';
import { embed, generateText } from 'ai';

async function ragAnswer(userQuestion: string) {
  // Step 1: Embed the question
  const { embedding } = await embed({
    model: openai.embedding('text-embedding-3-small'),
    value: userQuestion,
  });

  // Step 2: Retrieve relevant docs from vector DB
  const relevantDocs = await vectorDB.search(embedding, { topK: 5 });

  // Step 3: Augment prompt with retrieved context
  const context = relevantDocs.map(d => d.content).join('\n');

  // Step 4: Generate grounded answer
  const { text } = await generateText({
    model: openai('gpt-4o'),
    prompt: `Context:\n${context}\n\nQuestion: ${userQuestion}`,
  });

  return text;
}

4. What is Generative UI and AI SDK RSC?

🔥 Trending 2026
Simple Explanation
Generative UI allows the AI to render actual React components, not just text. The LLM decides which UI components to show based on the user's query.
Detailed Answer

Instead of returning a string like "Here is the weather: 25°C", the AI can return a rendered <WeatherCard temperature={25} /> React component. This enables richer, interactive AI responses.

Implemented via streamUI from ai/rsc in Next.js. The AI uses tool calls (function calling) to decide which component to render.

// app/actions.tsx — Generative UI with streamUI
'use server';
import { streamUI } from 'ai/rsc';
import { openai } from '@ai-sdk/openai';
import { WeatherCard } from '@/components/WeatherCard';
import { z } from 'zod';

export async function getWeather(city: string) {
  const result = await streamUI({
    model: openai('gpt-4o'),
    prompt: `Get weather for ${city}`,
    tools: {
      showWeather: {
        description: 'Show a weather card',
        parameters: z.object({ temp: z.number(), city: z.string() }),
        generate: async ({ temp, city }) => (
          <WeatherCard temperature={temp} city={city} />
        ),
      },
    },
  });
  return result.value;
}

5. What is Prompt Engineering and what techniques matter most?

🔥 Trending 2026
Simple Explanation
The craft of designing inputs (prompts) to get the best outputs from an LLM. Like writing precise instructions for a very intelligent but literal assistant.
Detailed Answer

Key techniques for frontend engineers building AI features:

  • System Prompt: Set the AI's persona, constraints, and output format.
  • Few-Shot Prompting: Give 2-3 examples in the prompt to demonstrate the expected format.
  • Chain-of-Thought: Ask the AI to "think step by step" for complex reasoning.
  • Structured Output: Use generateObject with Zod schema to get typed JSON instead of free text.
  • Temperature: Lower (0–0.3) for factual tasks, higher (0.7–1.0) for creative tasks.
// Structured Output — get typed JSON from AI
import { generateObject } from 'ai';
import { openai } from '@ai-sdk/openai';
import { z } from 'zod';

const { object } = await generateObject({
  model: openai('gpt-4o'),
  schema: z.object({
    sentiment: z.enum(['positive', 'negative', 'neutral']),
    score: z.number().min(0).max(100),
    summary: z.string().max(200),
  }),
  prompt: 'Analyze sentiment: "The product is amazing but shipping was slow."',
});

// object is fully typed: { sentiment: 'positive', score: 72, summary: '...' }
console.log(object.sentiment);

6. What is Tool Calling (Function Calling) in LLMs?

🔥 Trending 2026
Simple Explanation
A way for LLMs to request execution of specific functions. Instead of guessing, the AI says "call the getWeather(city) function" and your code executes it, then returns the result to the AI.
Detailed Answer

Tool calling enables AI agents — autonomous systems that can take actions, not just generate text. This is the foundation of AI copilots and agentic workflows.

The flow: User asks → AI decides which tool to call → Your code runs the tool → Result sent back to AI → AI generates final response.

import { generateText, tool } from 'ai';
import { openai } from '@ai-sdk/openai';
import { z } from 'zod';

const { text } = await generateText({
  model: openai('gpt-4o'),
  tools: {
    getWeather: tool({
      description: 'Get current weather for a city',
      parameters: z.object({ city: z.string() }),
      execute: async ({ city }) => {
        // Your actual API call
        const data = await fetch(`/api/weather?city=${city}`).then(r => r.json());
        return data;
      },
    }),
  },
  prompt: 'What is the weather in Tokyo?',
  maxSteps: 3, // Allow multi-step tool use
});

7. What are the best UX patterns for AI-powered features?

🔥 Trending 2026
Simple Explanation
AI interfaces require special UX patterns because responses are non-deterministic, slow, and can fail. Good AI UX handles these gracefully.
Detailed Answer

Essential AI UX patterns for senior frontend engineers:

  • Progressive Disclosure: Stream tokens as they arrive — don't make users wait for the full response.
  • Optimistic UI + Abort: Allow users to cancel in-progress generations with AbortController.
  • Skeleton Loading States: Show structured placeholders while AI generates.
  • Error Recovery: Handle rate limits, timeouts, and hallucinations with retry logic.
  • Human-in-the-Loop: Always allow users to edit, regenerate, or reject AI output.
  • Disclaimer/Attribution: Inform users when content is AI-generated (EU AI Act compliance).
// Abort an in-progress AI stream
const { stop, isLoading, messages } = useChat();

return (
  <div>
    {messages.map(m => <Message key={m.id} {...m} />)}

    {isLoading && (
      <div className="streaming-indicator">
        <span>AI is thinking...</span>
        <button onClick={stop}>⏹ Stop</button>
      </div>
    )}
  </div>
);

8. What is a Vector Database and when do you need one?

🔥 Trending 2026
Simple Explanation
A database optimized for storing and searching embeddings — numeric representations of text/images. Used to find semantically similar content (e.g., "find all documents about React hooks").
Detailed Answer

Traditional databases search by exact match. Vector databases search by semantic similarity using cosine distance or dot product.

Use cases in frontend apps:

  • Semantic Search: Search your docs/products by meaning, not keywords.
  • RAG: Find relevant context documents to inject into AI prompts.
  • Recommendation Engine: Find similar items based on content embeddings.

Popular options: Pinecone, Supabase pgvector, Weaviate, Qdrant.

// pgvector with Supabase — semantic search
import { createClient } from '@supabase/supabase-js';
import { embed } from 'ai';
import { openai } from '@ai-sdk/openai';

const supabase = createClient(URL, KEY);

async function semanticSearch(query: string) {
  // Convert query to embedding vector
  const { embedding } = await embed({
    model: openai.embedding('text-embedding-3-small'),
    value: query,
  });

  // Find similar documents using cosine similarity
  const { data } = await supabase.rpc('match_documents', {
    query_embedding: embedding,
    match_threshold: 0.78,
    match_count: 10,
  });

  return data;
}

10. How do you build responsible, safe AI-powered UIs?

🔥 Trending 2026
Simple Explanation
Responsible AI means preventing harm, bias, and misuse — it's not just ethical, it's becoming a legal requirement (EU AI Act, effective 2026).
Detailed Answer

Key responsibilities for frontend engineers building AI features:

  • Rate Limiting: Prevent API abuse with per-user request limits and cost controls.
  • Content Moderation: Use OpenAI Moderation API or similar to filter harmful inputs/outputs before displaying.
  • Transparency: Label AI-generated content clearly (EU AI Act Article 50 requirement).
  • Guardrails: System prompts should restrict scope (e.g., "Only answer about our product").
  • Data Privacy: Anonymize PII before sending to LLM APIs. Never send raw user data to third parties without consent.
  • Fallback UX: Always have a non-AI fallback path for when AI fails or is unavailable.
// Input moderation before calling LLM
import OpenAI from 'openai';

const openai = new OpenAI();

async function safeGenerate(userMessage: string) {
  // Step 1: Check for policy violations
  const moderation = await openai.moderations.create({
    input: userMessage,
  });

  if (moderation.results[0].flagged) {
    return {
      error: 'Message flagged for inappropriate content.',
      categories: moderation.results[0].categories,
    };
  }

  // Step 2: Proceed with generation (with system guardrails)
  const result = await streamText({
    model: openai('gpt-4o'),
    system: `
      You are a helpful customer support assistant for Acme Corp.
      ONLY answer questions about Acme's products and services.
      If asked about anything unrelated, politely decline.
      Never reveal confidential business information.
    `,
    messages: [{ role: 'user', content: userMessage }],
  });

  return result;
}

11. What are AI Agents and how do you build one on the frontend?

🔥 Trending 2026
Simple Explanation
AI Agents are LLM-powered systems that can autonomously plan, use tools, and execute multi-step tasks to achieve a goal — like a smart assistant that can search the web, read files, and write code.
Detailed Answer

Key components of an AI Agent:

  • Brain (LLM): The model that plans and reasons (GPT-4o, Claude 3.7).
  • Memory: Conversation history + vector store for long-term memory.
  • Tools: Functions the agent can call (search, API calls, code execution).
  • Orchestration: Loop that runs: Perceive → Think → Act → Observe.

The Vercel AI SDK's maxSteps parameter controls agent loops. Each "step" is one LLM call + tool execution.

// A simple multi-step AI Agent
import { generateText, tool } from 'ai';
import { openai } from '@ai-sdk/openai';
import { z } from 'zod';

const { text, steps } = await generateText({
  model: openai('gpt-4o'),
  maxSteps: 10, // Allow up to 10 tool-use loops
  tools: {
    searchWeb: tool({
      description: 'Search the web for information',
      parameters: z.object({ query: z.string() }),
      execute: async ({ query }) => searchAPI(query),
    }),
    writeCode: tool({
      description: 'Write and execute JavaScript code',
      parameters: z.object({ code: z.string() }),
      execute: async ({ code }) => executeSandbox(code),
    }),
    readFile: tool({
      description: 'Read a file from the project',
      parameters: z.object({ path: z.string() }),
      execute: async ({ path }) => fs.readFile(path, 'utf-8'),
    }),
  },
  prompt: 'Search for React 19 release notes and summarize the key features.',
});

// Agent autonomously decides: search → read results → generate summary
console.log(`Completed in ${steps.length} steps:`, text);

12. How do you design reusable React hooks for AI features?

🔥 Trending 2026
Simple Explanation
Just like any complex logic in React, AI interactions should be abstracted into custom hooks for reusability, testability, and separation of concerns.
Detailed Answer

A well-designed AI hook should handle: loading states, error states, streaming, abort signals, and retry logic. It should expose a clean, composable API to components.

Think of it as wrapping useChat or useCompletion with your business-specific logic (system prompt, model config, error handling) so components stay clean.

// hooks/useProductRecommendation.ts
import { useCompletion } from 'ai/react';
import { useCallback } from 'react';

interface UseProductRecommendationOptions {
  category: string;
  budget: number;
}

export function useProductRecommendation({ category, budget }: UseProductRecommendationOptions) {
  const { completion, isLoading, error, complete, stop } = useCompletion({
    api: '/api/recommend',
    onError: (err) => console.error('Recommendation failed:', err),
  });

  const getRecommendation = useCallback(async (userQuery: string) => {
    await complete(`Category: ${category}, Budget: $${budget}. Query: ${userQuery}`);
  }, [category, budget, complete]);

  return {
    recommendation: completion,
    isGenerating: isLoading,
    error,
    getRecommendation,
    cancelRecommendation: stop,
  };
}

// Usage in component — clean and testable!
function ProductSearch() {
  const { recommendation, isGenerating, getRecommendation } = useProductRecommendation({
    category: 'laptops',
    budget: 1500,
  });

  return (
    <div>
      <button onClick={() => getRecommendation('best for video editing')}>
        Get AI Recommendation
      </button>
      {isGenerating && <Spinner />}
      {recommendation && <RecommendationCard text={recommendation} />}
    </div>
  );
}
