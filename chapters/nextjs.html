1. App Router vs Pages Router?

Intermediate
Simple Explanation
Pages Router: File-system based routing in `pages/`. App Router: New paradigm in `app/` using Server Components by default.
Detailed Answer

App Router supports Layouts, Server Components, Streaming, and better data fetching patterns. It is the future of Next.js.

// Pages Router Structure
pages/
  index.tsx
  about.tsx

// App Router Structure
app/
  page.tsx
  about/
    page.tsx
  layout.tsx // Shared UI

2. When to use Client Components?

Intermediate
Simple Explanation
Use them when you need interactivity (onClick, onChange), hooks (useState, useEffect), or browser APIs.
Detailed Answer

By default, everything in App Router is a Server Component. Add 'use client' at the top of the file to make it a Client Component. Server Components cannot use hooks or event listeners.

'use client'; // Marks this as a Client Component

import { useState } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

3. How do you fetch data in App Router?

Advanced
Simple Explanation
Using standard async/await in Server Components.
Detailed Answer

You can fetch data directly in the component body. Next.js extends the native fetch API to allow caching and revalidation configuration (e.g., next: { revalidate: 3600 }).

async function getData() {
  const res = await fetch('https://api.example.com/data');
  if (!res.ok) throw new Error('Failed to fetch data');
  return res.json();
}

export default async function Page() {
  const data = await getData();
  return <main>{/* ... */}</main>;
}

4. Static vs Dynamic Rendering in Next.js?

Advanced
Simple Explanation
Static: Prerendered at build time (default). Dynamic: Rendered at request time.
Detailed Answer

Next.js automatically switches to dynamic rendering if you use dynamic functions (cookies, headers) or uncached data fetches.

// Force Dynamic Rendering
export const dynamic = 'force-dynamic';

// Or use dynamic functions
import { cookies } from 'next/headers';
const cookieStore = cookies();

5. How does the Next.js Image component optimize images?

Intermediate
Simple Explanation
It automatically resizes, compresses, and serves images in modern formats (WebP/AVIF) based on the user's device.
Detailed Answer

It also prevents Layout Shift (CLS) by requiring width/height or fill mode, and lazy loads images by default.

import Image from 'next/image';

<Image
  src="/profile.png"
  width={500}
  height={500}
  alt="Profile Picture"
/>

6. What is Middleware in Next.js?

Advanced
Simple Explanation
Code that runs before a request is completed. Useful for authentication, redirects, and rewriting paths.
Detailed Answer

It runs on the Edge runtime (limited Node.js APIs). You can modify the request or response headers and redirect users based on conditions (e.g., checking a cookie).

// middleware.ts
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  if (request.nextUrl.pathname.startsWith('/dashboard')) {
    return NextResponse.rewrite(new URL('/auth/login', request.url));
  }
}

7. What is ISR?

Advanced
Simple Explanation
Allows you to update static pages after you've built your site.
Detailed Answer

You can retain the benefits of static generation while scaling to millions of pages. Pages are regenerated in the background as traffic comes in, based on a revalidation interval.

// Revalidate every hour
export const revalidate = 3600;

export default async function Page() {
  const data = await fetch('...', { next: { revalidate: 3600 } });
  return ...
}

8. What are Route Handlers?

Intermediate
Simple Explanation
The equivalent of API routes in the App Router (route.ts files).
Detailed Answer

They allow you to create custom request handlers for a given route using the Web Request and Response APIs. Support GET, POST, PUT, PATCH, DELETE, HEAD, and OPTIONS.

// app/api/hello/route.ts
export async function GET(request: Request) {
  return Response.json({ message: 'Hello World' });
}

9. How do you handle SEO in App Router?

Intermediate
Simple Explanation
Using the Metadata API (exporting a metadata object or generateMetadata function).
Detailed Answer

It replaces the old Head component. You can define title, description, open graph tags, etc., either statically or dynamically based on route params.

// Static Metadata
export const metadata = {
  title: 'My Page',
  description: 'This is my page',
};

// Dynamic Metadata
export async function generateMetadata({ params }) {
  return {
    title: `Product ${params.id}`,
  };
}

10. How do Server Actions work in Next.js?

Advanced
Simple Explanation
They allow you to call server-side functions directly from client components (e.g., form actions).
Detailed Answer

Next.js handles the API endpoint creation automatically. It's great for mutations. You can use revalidatePath to update the UI after the action completes.

// app/actions.ts
'use server';

export async function createTodo(formData: FormData) {
  await db.todo.create({ title: formData.get('title') });
  revalidatePath('/todos');
}

11. What is Partial Pre-rendering (PPR) in Next.js 15?

🔥 Trending 2026
Simple Explanation
PPR lets you render part of a page statically (instant, from CDN) and stream dynamic parts (personalized content) — all in a single request. The best of both static and dynamic.
Detailed Answer

Previously you had to choose: fully static (fast, not personalized) OR fully dynamic (slower, personalized). PPR eliminates this trade-off.

The static shell (layout, navigation) is served instantly from CDN. Dynamic holes (user name, recommendations) stream in via Suspense boundaries — all in one HTTP request.

Enable with: experimental: { ppr: true } in next.config.js.

// next.config.js
module.exports = {
  experimental: { ppr: true }, // Enable PPR
};

// app/page.tsx — Static shell + dynamic Suspense holes
import { Suspense } from 'react';
import { UserGreeting } from './UserGreeting'; // Dynamic (personalized)
import { StaticHero } from './StaticHero';     // Static (from CDN instantly)

export default function Page() {
  return (
    <main>
      {/* Served immediately from CDN edge */}
      <StaticHero />
      <StaticNavigation />

      {/* Streams in after — personalized, dynamic */}
      <Suspense fallback={<GreetingSkeleton />}>
        <UserGreeting /> {/* Reads cookies, hits DB */}
      </Suspense>
    </main>
  );
}

12. What is Turbopack and how does it improve Next.js dev experience?

🔥 Trending 2026
Simple Explanation
Turbopack is a Rust-based bundler that replaces Webpack in Next.js. It's dramatically faster for local development — up to 10x faster builds than Webpack.
Detailed Answer

Turbopack became stable for next dev in Next.js 15. Key advantages:

  • Incremental computation: Only rebuilds what changed — caches at the function level.
  • Rust-powered: Multi-threaded, memory-safe, extremely fast cold start.
  • HMR (Hot Module Replacement): Near-instant updates — even on large apps with thousands of modules.
  • Still Webpack for production: next build still uses Webpack/SWC in stable versions.
# Enable Turbopack for dev (stable in Next.js 15)
next dev --turbopack

# Or in package.json
{
  "scripts": {
    "dev": "next dev --turbopack"
  }
}

# next.config.js — Custom Turbopack config
module.exports = {
  turbopack: {
    resolveAlias: {
      // Custom module aliases
      '@components': './src/components',
    },
    rules: {
      // Custom file loaders
      '*.svg': { loaders: ['@svgr/webpack'], as: '*.js' },
    },
  },
};

13. What is unstable_after in Next.js 15?

🔥 Trending 2026
Simple Explanation
A new Next.js API that lets you run code after a response is sent — without blocking the user. Perfect for analytics logging, sending emails, or other side effects.
Detailed Answer

Previously, any code you wanted to run after a request (like logging analytics) would either block the response or require a separate background job service. after() solves this elegantly.

The response streams to the user immediately. The after() callback runs after the response is fully sent, without delaying the user.

import { unstable_after as after } from 'next/server';
import { log } from '@/lib/analytics';

export default async function Page({ params }) {
  // This data fetching blocks until ready (for the user)
  const product = await fetchProduct(params.id);

  // Log analytics AFTER response is sent — user isn't waiting!
  after(async () => {
    await log({ event: 'product_view', productId: params.id });
    await sendViewNotification(product.sellerId);
  });

  return <ProductPage product={product} />;
}

// Also works in Route Handlers and Server Actions
export async function POST(req: Request) {
  const data = await req.json();
  const result = await processOrder(data);

  after(async () => {
    await sendOrderConfirmationEmail(data.email); // Non-blocking!
  });

  return Response.json({ success: true, orderId: result.id });
}
